# AI 论文阅读助手 —— 设计文档

日期：2026-09-10
状态：已与需求方确认

## 1. 背景与目标

研究生读英文论文时反复遇到三件麻烦事：读得慢（语言障碍）、读不完（没时间通读）、读不懂（引用的参考文献不知道是什么）。这个软件把这三件事一次性解决掉。

软件是一个 Windows 桌面应用，双击一个 exe 就能跑，不需要安装、不需要服务器、不需要账号。所有数据存在本地，AI 能力由用户自己提供（云端 API key 或本地大模型）。

### 目标用户

一名研一学生，非计算机专业，会读论文但不会写代码。对命令行、环境变量、配置文件没有概念，期望"下载一个文件 → 双击 → 能用"。

### 成功标准

用户能独立完成以下流程，全程不需要求助他人：

1. 把一篇英文 PDF 拖进软件，正文被正确切分成段落
2. 点一下"全文翻译"，几分钟内得到左右对照的中文
3. 中途关掉软件再打开，未完成的部分能继续，不重复调用 AI
4. 得到一份结构化的中文总结（研究问题 / 方法 / 数据 / 结论 / 创新点 / 局限）
5. 看到参考文献列表，点其中一条能看到"这篇讲了什么、在本文里起什么作用"
6. 把整篇论文的译文、总结、文献概述导出成一个 Markdown 文件

任何一步卡住，软件都要用中文说清楚卡在哪、怎么办，而不是抛出一个英文错误。

## 2. 关键决策

以下决定已经与需求方逐条确认，实现阶段不再重新讨论。

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| 1 | 交付形态 | 本地桌面应用，单个 exe 直启，无安装 | 目标用户不会配置环境 |
| 2 | 数据存放 | 全部本地文件，无云端、无账号、无服务器 | 无服务器预算 |
| 3 | AI 接入 | 用户自带 API key + 用户自建本地模型，两者都走 OpenAI 兼容协议 | 覆盖零成本到高性能全区间 |
| 4 | 翻译呈现 | 默认干净原文阅读器；点"全文翻译"生成左右对照；选中文字可即时翻译 | 尊重论文自身的排版 |
| 5 | 原文渲染 | 用 pdf.js 渲染 PDF **原版排版**，不重排 | 图表公式的位置本身就是信息 |
| 6 | 总结形态 | 固定结构卡片 + 每张卡片带 TL;DR，可展开 | 输出可预期，便于横向对比论文 |
| 7 | 总结位置 | 底部可折叠横条 | 全局信息常驻视野，但不侵占阅读区 |
| 8 | 参考文献位置 | 右侧可滑出抽屉 | 条目式内容，按需查看 |
| 9 | 参考文献精度 | 元数据 + 摘要级（OpenAlex / CrossRef / Semantic Scholar），不做全文抓取 | 快、免费、无版权风险 |
| 10 | 查不到的文献 | 标注"未识别"并保留原文，交给用户手动处理 | 精确率做不到 100%，不假装做到了 |
| 11 | 数据组织 | 论文库模式（文件夹、标签、搜索） | 用户毕业前会积累上百篇 |
| 12 | 导出 | 支持导出 Markdown 笔记 | 成本低，把"读论文"接到"整理知识" |
| 13 | 技术栈 | Electron + React + TypeScript | 本机已有 Node，无 Rust / 无 Python |
| 14 | 存储方案 | JSON 文件，不用数据库 | 避免原生模块编译，且用户可直接查看和备份 |

## 3. 系统架构

三层，权限严格单向。

### 3.1 渲染进程（React，无权限）

只负责画界面和收集输入。**没有文件权限，没有网络权限，不持有 API key。**包含五个界面模块：

- **论文库**：列表、文件夹、标签、搜索、拖拽导入
- **阅读器**：pdf.js 渲染页面 canvas + 透明文本层（用于选中和划词）
- **译文面板**：按段落流式填充，与原文滚动同步
- **总结卡片**：底部横条，TL;DR 常驻，点击展开七张结构卡片
- **文献面板**：右侧抽屉，列表 + 详情

### 3.2 预加载桥（preload / contextBridge）

一层窄接口，把主进程能力暴露为 `window.api.*`。渲染进程只能调用这里列出的方法，无法绕过。开启 `contextIsolation`，关闭 `nodeIntegration`。

### 3.3 主进程（Node，唯一特权层）

四个职责：

- **库管理**：导入、复制 PDF、读写每篇论文的数据文件、维护索引
- **AI 网关**：加密存储 key、发起流式请求、重试与降级、并发控制、token 与费用估算
- **文献检索**：调用 OpenAlex / CrossRef / Semantic Scholar，做标题模糊匹配与置信度判断
- **任务队列**：翻译与总结任务的排队、进度上报、取消、断点续传

### 3.4 外部依赖

- **本地库目录**：普通文件夹，PDF + JSON
- **AI 服务**：DeepSeek / 智谱 / Kimi / 通义 / OpenAI（自定义 Base URL），或本地 Ollama / LM Studio
- **学术接口**：OpenAlex、CrossRef、Semantic Scholar —— 全部免费且无需 key

## 4. 数据模型与存储

### 4.1 目录结构

库目录默认是 `C:\Users\<用户名>\Documents\我的论文\`，可在设置里更改。

```
我的论文/
  index.json                    索引：全部论文的元信息与状态
  papers/
    a3f9c1/                     每篇论文一个文件夹，ID 为随机短串
      paper.pdf                 原始 PDF 的副本
      meta.json                 标题、作者、年份、DOI、来源路径、导入时间、标签
      blocks.json               抽取出的原文段落（含页码与坐标）
      translation.zh.json       逐段译文与状态
      summary.zh.json           总结卡片
      references.json           参考文献解析结果、外部查询结果、AI 概述
```

程序自身的配置单独存放，与论文库分离，位置为 `%APPDATA%\ai-paper-reader\`：

```
config.json                     界面偏好、当前使用的 AI 配置编号、库目录路径
ai-profiles.json                多套 AI 配置（Base URL、模型名），API Key 单独加密存放
ai-keys.bin                     API Key 密文（Windows DPAPI 加密）
```

论文库可以整个拷走或删除，不影响程序配置；反过来也一样。用户换电脑时，只拷"我的论文"文件夹即可带走全部成果。

### 4.2 三个设计要点

**导入时复制 PDF，而不是记录路径。** 用户清理下载文件夹、拔掉 U 盘，都会让只记路径的库彻底失效，而此时已经花掉了 token。复制一份（单篇 5–20MB）彻底消除这个风险。

**`blocks.json` 是系统里最有价值的中间产物。** 它是"把 PDF 拆成段落、每段知道自己在第几页哪个位置"的结果。翻译、滚动同步、总结、文献定位全部依赖它。算好一次永久复用，因此重复打开同一篇论文是秒开的。

**AI 结果按段落存储，不按整篇存储。** 中途关软件、断网、模型报错都不会让已完成的翻译作废，重新打开只补未完成的段落，不重复花钱。

### 4.3 主要数据结构

`blocks.json` —— 段落是翻译与对齐的最小单位：

```
{
  "paperId": "a3f9c1",
  "extractedAt": 1789000000000,
  "pageCount": 11,
  "blocks": [
    {
      "id": "p3-b07",
      "page": 3,
      "bbox": { "x": 54, "y": 212, "w": 240, "h": 48 },
      "type": "paragraph",          // heading | paragraph | caption | reference | other
      "text": "We propose a new ...",
      "sectionPath": ["3", "3.2"]    // 可选，用于定位章节
    }
  ]
}
```

`translation.zh.json` —— 每个段落一个状态：

```
{
  "targetLang": "zh",
  "model": "deepseek-chat",
  "updatedAt": 1789000000000,
  "blocks": {
    "p3-b07": { "status": "done", "text": "我们提出了一种新的……" },
    "p3-b08": { "status": "failed", "error": "rate_limited", "attempts": 3 }
  }
}
```

段落状态机：`pending → streaming → done`，或 `pending → failed`（可重试回到 pending）。另有 `skipped` 用于检测为无需翻译的内容（如公式行、纯数字表格）。

## 5. 四条主链路

### 5.1 导入

拖入 PDF → 主进程把文件复制进 `papers/<id>/` → 用 pdf.js 抽取每页文本（含坐标）→ 段落重建 → 猜标题与作者（优先读 PDF 内嵌元数据，其次取首页字号最大的文本块）→ 写入 `meta.json` 与 `blocks.json` → 更新 `index.json` → 出现在列表里。

**全程本地，不调 AI、不联网。** 导入上百篇也是秒级完成。

段落重建算法是整套系统的地基：

1. 逐页取文本片段（pdf.js `getTextContent()`），带坐标
2. 按 y 坐标聚类成"行"
3. 按 x 分布判断栏数——双栏 PDF 会出现明显的 x 断层，据此把行分组，保证阅读顺序是"左栏读完再读右栏"
4. 同栏内相邻行合并成段：行距连续、且上一行没有以句末标点结尾、下一行以小写字母或连接词开头
5. 识别并剔除页眉页脚（在每页固定位置反复出现的文本）
6. 识别参考文献区（文末且大量条目以 `[n]` 或作者姓氏开头）

### 5.2 全文翻译

点"全文翻译" → 按 token 预算把段落分批（每批 8–12 段）→ 3–4 路并发请求 → 每批返回"段落号 → 译文"的 JSON → 实时写入 `translation.zh.json` → 界面逐段浮现中文。

批次边界会避开跨段落，并且整批失败时不影响已落盘的批。中断后重启只补 `pending` 与 `failed` 的段落。

### 5.3 总结

取 `blocks.json` 全文 → 短论文（低于模型上下文预算）一次性总结；超长论文走 map-reduce：先按章节分段粗读得到中间摘要，再把中间摘要合并成最终结构 → 模型输出固定 JSON 结构 → 存入 `summary.zh.json`。

固定结构为七项：一句话总结、研究问题、方法、数据与实验、主要结论、创新点、局限性。

### 5.4 参考文献反查

解析文末参考文献表 → 切成条目（按 `[n]` 编号或悬挂缩进分割）→ 逐条解析出标题、作者、年份、期刊 → 以标题为主键查询 OpenAlex（主）、CrossRef（备）、Semantic Scholar（补摘要）→ 得到 DOI、作者、年份、期刊、摘要 → 让 AI 生成两部分内容：**这篇文献本身讲了什么**，以及**它在当前论文里扮演什么角色**（方法来源 / 对比基线 / 数据集出处 / 背景引用）。

第二部分是这套设计的核心价值：光有被引文献的摘要，对理解当前论文帮助有限；知道"作者为什么引它"才真正有帮助。

触发方式：点击单条查询，另有一键处理全部（带限流）。

## 6. 界面与交互

### 6.1 论文库

左侧论文列表（文件夹与标签组织，顶部搜索），每篇右侧显示状态角标：未翻译 / 翻译中 40% / 已完成。拖入 PDF 即导入。

### 6.2 阅读界面的三个状态

**状态一 · 干净阅读态（默认）**

顶部工具栏：返回库、论文标题、`全文翻译`、`总结`、`参考文献`、`导出`。主区左原文右译文。底部折叠条只显示一行 TL;DR 和展开箭头。

**状态二 · 精读态**

点"参考文献"或点击正文中的引用编号 `[23]`，右侧抽屉滑出并定位到第 23 条。**抽屉滑出时阅读区是被挤窄的，不是被遮住的**，以便一边看原文一边看引用说明。抽屉内的引用条目展示：编号、AI 中文概述、原文标题、作者年份期刊、DOI 链接。

**状态三 · 总结展开态**

点底部折叠条展开为七张卡片横排，点任意卡片就地展开详细解释。整条可随时折回，回到干净阅读态。

### 6.3 局部翻译

在原文区选中任意文字，就地弹出译文气泡。这条链路只发送选中的内容，不消耗全文额度。

### 6.4 滚动同步

左侧原文滚动时，按当前可见 `block` 的 bbox 计算出对应的段落 id，把右侧译文滚动到同一节点。用程序滚动期间短暂锁定事件（约 200ms）避免两边互相追逐。滚动同步是单向的，只有原文驱动译文。

### 6.5 设置页

- AI 配置：可保存多套并切换，每套包含名称、Base URL、模型名、API Key、并发数
- "测试连接"按钮：立即验证 key 与模型是否可用，失败时给中文原因
- 本地模型：启动时探测 Ollama 服务，给出人话提示
- 库目录位置
- 目标语言（第一版固定中文，界面留位）

### 6.6 费用显示

顶部角落显示累计 token 估算与折算金额。用 API 的用户最焦虑的是"点这一下要花多少钱"，把数字摊在明面上比写说明更有效。金额按内置的常见模型单价表估算，用户可覆盖。

## 7. AI 接入层

统一按 OpenAI 兼容的 `/chat/completions` 协议实现，用户只需填 Base URL、模型名、API Key（本地模型 Key 可留空）。这一层覆盖 DeepSeek、智谱、Kimi、通义、OpenAI、Ollama、LM Studio。

需要单独兜底的能力：

- 流式输出（SSE 解析）
- JSON 输出模式的兼容差异
- 不同服务的上下文长度差异（用于决定分批大小）

API Key 用系统提供的加密能力（Windows DPAPI）加密后落盘，不上传、不写进 exe、不出现在日志里。

## 8. 错误处理与边界情况

| 情况 | 处理方式 |
|---|---|
| 网络波动、限流 429 | 自动重试，指数退避 1s→2s→4s，最多三次；同时自动降低并发 |
| API Key 无效、余额不足 | 不重试，明确中文提示 + 跳转设置页 |
| 模型返回非法 JSON | 先整批重试，仍失败则拆成单段逐条翻译（慢但可靠） |
| 输出被截断（finish_reason=length） | 缩小批次重新翻译该批 |
| 用户中途关闭软件 | 状态实时落盘，重启时横幅提示"还有 N 段未翻译，继续？" |
| 本地模型服务未启动 | 提示检测不到服务并给出启动方式 |
| 本地模型名称错误或未下载 | 给出具体提示，而不是透出 404 |
| PDF 加密或损坏 | 明确报错，不静默失败 |
| 扫描版 PDF（无文字层） | 检测到直接提示"需要 OCR，暂不支持" |
| 超长 PDF（200 页以上） | 分页懒加载渲染，导入时后台分批解析 |
| 参考文献匹配不到 | 标记"未识别"，保留原始文本，支持手动补 DOI 或标题重查 |
| 库目录不可写、磁盘空间不足 | 导入前检查并提前提示 |
| 论文本身是中文 | 检测语言后调整按钮语义，以"总结"为主 |

原则：任何失败都必须让用户知道**哪一步失败了、能不能重试、怎么解决**，且**绝不丢弃已完成的结果**。

## 9. 测试策略

**地基测试（必须有）**：段落切分与参考文献条目解析是全部功能的前提。准备 3–5 篇风格不同的真实论文作为固定样例——单栏、双栏、无编号引用、含大量公式、含中英混排——每次改动都跑一遍。

**流程测试**：本地写一个假的 AI 服务（mock），返回固定响应，跑完整的"翻译 → 中断 → 重启 → 续传"流程。既验证断点续传逻辑，又不花真钱。

**AI 输出的容错测试**：mock 服务刻意返回非法 JSON、截断输出、429 错误，验证降级路径。

**打包验证**：产出 portable exe 后，在一台没装过任何开发工具的 Windows 上双击验证完整流程。

**人工验收清单**：导入 → 翻译 → 关闭 → 重开续传 → 总结 → 文献 → 导出 Markdown → 更换 AI 配置 → 换一篇双栏论文重来一遍。

## 10. 第一版明确不做

以下功能经确认移出第一版范围：

- 扫描版 PDF 的 OCR
- AI 问答对话（对着全文提问）
- 云端同步、账号体系、多设备
- 手机端、macOS 与 Linux 版本
- 图表与公式的翻译
- 自动下载被引论文的全文
- 多目标语言（先固定英译中，代码结构上预留）
- 论文库的导入导出与共享

## 11. 技术选型

- **壳**：Electron
- **界面**：React + TypeScript + Vite
- **PDF**：pdfjs-dist（渲染与文本抽取同一套引擎）
- **打包**：electron-builder，portable 目标，产出单个 exe，无需安装
- **存储**：文件系统 + JSON，不引入数据库
- **密钥**：Electron `safeStorage`（底层为 Windows DPAPI）
- **网络请求**：主进程内发起，避免跨域问题且不暴露 key

选 Electron 而非 Tauri 的原因：本机已具备 Node 20 与 npm，而 Rust 与 Visual Studio C++ 生成工具均未安装，补齐需要下载 6–8GB。Tauri 的体积优势（约 10MB 对比约 120MB）不足以抵消这套配置成本与后续排查难度。

不用数据库的原因：SQLite 在 Electron 中需要编译原生模块，本机缺少 C++ 生成工具，大概率直接失败；而论文库这种规模用 JSON 完全够用，且用户可以直接查看和备份数据。

## 12. 已知风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 双栏 PDF 的阅读顺序判断错误 | 译文顺序错乱，用户信任度下降 | 段落切分准备多篇真实样例做回归；界面允许用户手动合并或拆分段落 |
| 参考文献条目解析准确率不足 | 部分条目无法反查 | 定位为"大部分能用即可"，未识别条目交给用户手动处理 |
| 小模型返回非法 JSON | 批量翻译失败 | 自动降级为单段翻译 |
| 用户 Key 额度耗尽中途失败 | 翻译中断 | 状态落盘，充值后可继续，不重复计费 |
| 首次使用需要用户自行注册并获取 API Key | 存在上手门槛 | 设置页内置图文指引；本地模型作为零成本替代路径 |
